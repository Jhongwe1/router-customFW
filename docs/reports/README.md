# Gate results, indexed

[`docs/GATE-RESULTS.md`](../GATE-RESULTS.md) is written on the day each gate closes: one line,
the claims that stand with their evidence, and what the gate did not establish. It is a record —
an entry is never edited after its segment, and a correction is a later entry or a `SPEC.md` row.
This page indexes it: one row per entry, each summarising its entry and linking it, holding no
number the entry does not. Built at `e949311f` (2026-10-17).

**What counts as an entry:** a level-2 heading `## YYYY-MM-DD — <gate> (…)`. The file has 27
level-2 headings; 23 match. The four that do not are its preface — *What this file is for,
beyond the record*, and *Two gates are missing from the top of this file, deliberately* (`S0`
and `R0` closed before the ledger existed and are not backfilled) — and its close: *The
operating clause, re-run at twenty-three entries* and *What this file does not do*. So the table
has 23 rows, and each gate links its entry's heading.

## What this page does not establish

Each row is its entry on the day it was written. This page re-verifies no claim, and a claim
corrected later is corrected in a later entry or a `SPEC.md` row, not here — `P4b`'s *not
released*, for one, was overtaken the same day, when `v1.0` was published (`CHANGELOG.md`). A
claim's evidence is named as its entry names it, a path or an id; R9's third claim is left out
to keep the cap of three.

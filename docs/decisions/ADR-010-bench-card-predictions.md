# ADR-010: Bench cards carry predictions frozen before power — and the relaxation of 2026-09-27

## Context
One power cycle of the only unit is the most expensive unit of work here, and nothing counts as a result until its refutation condition was written first. The first run sheet's house rule 2: "A cell whose expectation is written afterwards illustrates; it cannot refute." From 2026-08-24 the console was driven directly instead of relayed cell by cell, and a prediction written after a reading became indistinguishable from one written before it.
## Decision
Each seating's card lists its cells and their expected values before power, is frozen (`git add`, `spec-check`, commit) and is never edited; a correction goes into a new `CORRECTIONS-*.md`. `tools/check-predictions.py` checks that every capture a card names is newer than the card.
**The relaxation.** On 2026-09-27 the owner relaxed this for `R6b` only — no freeze, predictions optional, test while building — because the gate had run past the segment count the owner had in mind and what it had to measure and build still had to be done. `R1y` carried it over; on 2026-09-30, opening `R7` and `R8a`, the owner widened it: the goal became finishing the task, with no frozen cards, predictions only where they earn it, no desk-sweep and the relevant minimum of checks per commit. **Not relaxed:** the flash rules (`cardcheck` still refuses the write verbs), `H601`, the power handshake, and `NET-165` — no unattended wait at the loader prompt, ruled the same night after the loader, about two hours at its prompt, accepted `IPCONFIG` and answered no ARP (量).
## Alternatives considered
- **Expectations in messages to the operator**, the first mechanism: the rule enforced itself while the operator relayed each cell, because the message had already been sent, and it lost its enforcer when the console was handed over; `check-predictions` replaced it.
- **A committed `written:` line inside each prediction file**: not built, because cards already frozen cannot carry one; the ordering check stayed a pre-push gate.
## Consequences
- mtime is not a cryptographic timestamp and does not survive git — 量 2026-08-29, 128 of 156 cells read older than their prediction in a fresh clone — so the check proves the order only on the machine that took the captures. Fixing a typo in a frozen card fails it.
- From `R6b`'s block 51 (2026-09-27) on, cells ran from committed, unfrozen cards: the mtime evidence does not exist for `R6b`'s `D7`, `D8` or `NET-25`. `R6c` kept its card's.
- `R9` closed in 3 segments against a board estimate of 16, which its entry attributes to the relaxation of 2026-09-27 and to eight of its steps being desk work over files that already existed.
